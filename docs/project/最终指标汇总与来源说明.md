# 最终指标汇总与来源说明

## 1. 文件用途

本文档用于说明论文、答辩稿和前端页面中使用的核心实验指标来自哪里，避免答辩时出现“指标来源不清楚”的问题。

当前项目中的最终指标不是由前端页面实时计算得到的，而是由实验结果表整理后导出为前端 JSON，再由 `dashboard_fixed.html` 读取展示。

## 2. 指标来源链路

当前指标链路如下：

```text
p1结果展示.md
  -> export_frontend_metrics.py
  -> results/frontend_metrics.json
  -> dashboard_fixed.html
```

同时，论文和答辩中使用的表格整理在：

```text
论文表格汇总.md
```

说明：

- `p1结果展示.md`：原始模型对比表和消融实验表。
- `export_frontend_metrics.py`：将 Markdown 表格解析为前端可读取的 JSON。
- `results/frontend_metrics.json`：前端展示使用的指标文件。
- `论文表格汇总.md`：论文和答辩材料中可直接使用的整理版表格。
- `results/metrics.jsonl`：训练脚本 `train.py` 追加写入的实验日志文件。如果没有重新训练，当前文件可能为空，不作为本次答辩展示指标的主要来源。

## 4. 主模型最终结果

| 数据集 | 模型 | AUC-PR | AUC-ROC | F1 | Accuracy | Recall |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| NYC | Myplan | 0.6955 | 0.8786 | 0.6443 | 0.7865 | 0.8265 |
| Chicago | Myplan | 0.5617 | 0.8290 | 0.4730 | 0.7733 | 0.7055 |

来源：

- 整理版表格：`论文表格汇总.md`
- 前端指标文件：`results/frontend_metrics.json`
- 原始展示表：`p1结果展示.md`

答辩表述建议：

> 从实验结果看，Myplan 在 NYC 和 Chicago 两个数据集上都取得了较好的 AUC-PR、AUC-ROC、F1 和 Recall 表现，说明动态演化、空间注意力和平滑策略对交通碰撞风险识别有一定提升作用。

## 6. 消融实验结果位置

完整消融实验结果见：

```text
论文表格汇总.md -> 表 5 NYC 消融实验结果
论文表格汇总.md -> 表 6 Chicago 消融实验结果
```

消融配置包括：

| 配置 | 含义 |
| --- | --- |
| 去平滑门 + 去流式后处理 | 同时关闭自适应平滑门和 Streaming 后处理 |
| 去平滑门 | 关闭模型内部自适应平滑门 |
| 去流式后处理 | 关闭输出端 Streaming 后处理 |
| 完整模型 | 同时使用自适应平滑门和 Streaming 后处理 |

答辩表述建议：

> 消融实验说明，自适应平滑门主要作用于模型内部动态特征，使动态表示更稳定；Streaming 后处理主要作用于模型输出端，使预警结果在阈值附近不频繁抖动。两者作用位置不同，完整模型整体表现更稳定。

## 8. 答辩中关于指标的稳妥回答

如果老师问“这些指标从哪里来的”，可以回答：

> 指标首先整理在 `p1结果展示.md` 的模型对比表和消融实验表中，然后通过 `export_frontend_metrics.py` 导出为 `results/frontend_metrics.json` 供前端读取。论文中使用的整理版表格在 `论文表格汇总.md`，本文件进一步说明了指标来源链路。

如果老师问“为什么 `results/metrics.jsonl` 是空的”，可以回答：

> `results/metrics.jsonl` 是训练脚本重新运行时追加写入的日志文件。当前答辩展示使用的是已经整理好的实验结果表和前端指标 JSON，因此没有依赖这个空日志文件。

如果老师问“为什么 Accuracy 不是最高”，可以回答：

> 交通碰撞预测是类别不平衡任务，单独追求 Accuracy 容易偏向多数类。本文更关注 AP、AUC、F1 和 Recall 等指标，尤其是 Recall，因为漏报高风险区域在交通安全场景下代价更高。
