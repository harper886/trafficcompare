# 现场演示脚本

## 演示前准备

提前在项目根目录启动：

```powershell
python -m http.server 8000
```

浏览器提前打开：

```text
http://localhost:8000/dashboard_fixed.html
```

如果现场网络或页面异常，直接使用备用截图：

```text
assets/frontend-real-screenshot.png
```

## 1. 打开首页

**操作**

打开 `dashboard_fixed.html`。

**讲解**

这是本项目实现的交通碰撞风险预测可视化大屏。页面默认加载后端导出的前端 JSON 文件，包括 NYC 和 Chicago 的预测样本、模型指标和空间拓扑关系。

## 2. 说明数据来源

**操作**

指向页面上的“答辩数据说明”区域。

**讲解**

前端展示的是后端从真实数据和模型结果中导出的代表性样本。NYC 展示 13 个时间帧、64 个区域，共 832 条区域-时间记录；Chicago 展示 13 个时间帧、27 个区域，共 351 条区域-时间记录。这样设计是为了保证浏览器运行流畅。

## 3. 城市切换

**操作**

点击 Chicago / New York 切换按钮。

**讲解**

系统支持双城数据展示。切换城市后，风险热力图、区域列表、模型指标和局部解释信息都会同步更新。

## 4. 时间轴播放

**操作**

拖动时间轴，或点击播放按钮。

**讲解**

时间轴用于展示不同代表性时间帧下的风险变化。交通碰撞风险不是静态的，而是随时间和区域状态不断变化。

## 5. 地图区域交互

**操作**

点击或悬停地图上的高风险区域。

**讲解**

点击区域后，系统会联动更新右侧解释面板，包括风险概率、当前流量、历史均值、流量偏差、真实标签校验和邻接关系。

## 6. TP / FP / FN 解释

**操作**

切换到真实标签校验相关视图，或指向页面中的 TP / FP / FN 信息。

**讲解**

TP 表示模型成功命中真实风险，FP 表示误报，FN 表示漏报。交通安全预警中漏报代价较高，因此本项目更重视 Recall。

## 7. 模型指标展示

**操作**

指向模型对比图和消融实验图。

**讲解**

系统展示了多个模型的对比结果，包括 AUC-PR、AUC-ROC、F1、Accuracy 和 Recall。本文模型在两个城市数据集上都取得了较好的综合表现，尤其在召回率上更适合交通预警场景。

## 8. 空间邻接解释

**操作**

指向局部邻接拓扑面板。

**讲解**

交通风险不仅与当前区域自身有关，也与道路连接、POI 功能和历史事故关联有关。这个面板展示了当前区域与其他区域之间的局部空间关系，用于增强模型结果的解释性。

## 9. 系统边界说明

**讲解**

需要说明的是，当前系统是离线预测与可视化原型，没有接入实时交通接口。前端展示的是后端导出的代表性样本，而不是直接加载全量 `.npy` 文件。后续可以继续扩展实时数据接入、真实 GIS 边界和在线预警服务。

## 10. 演示结束总结

**讲解**

通过这个系统，可以完成从交通风险预测结果到可视化解释的展示流程。它不仅展示风险位置和概率，还结合真实标签校验、实验指标和空间邻接关系，为模型结果解释和答辩展示提供支撑。

## 常见现场问题快速回答

**问：为什么页面只展示 13 帧？**

答：原始时序数据较大，前端直接加载会影响性能，所以抽取代表性时间帧用于交互展示；完整训练和评估仍基于后端全量数据完成。

**问：这是实时系统吗？**

答：不是。当前是离线预测与可视化原型，后续可以接入实时交通接口扩展为在线系统。

**问：数据真实吗？**

答：核心预测概率、流量特征、标签校验、模型指标和拓扑关系来自本地数据和模型导出；部分区域描述和展示文案用于增强可读性。

**问：为什么重视 Recall？**

答：交通安全预警中漏报代价更高，因此需要尽量发现真实风险区域，Recall 对这个场景更关键。
