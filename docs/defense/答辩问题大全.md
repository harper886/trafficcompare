# 交通碰撞风险预测项目答辩问题大全

本文档用于答辩前快速准备老师可能追问的问题。回答时不要把系统说成实时生产平台，也不要把已有 Attention-LSTM 基础框架说成完全原创。更稳妥的表述是：本文在已有时空风险预测框架基础上，围绕动态特征稳定性、输出后处理、实验验证和可视化展示进行了改进与实现。

## 一、项目总体类

### 1. 你的项目主要做了什么？

答：本项目面向城市交通碰撞风险预测任务，使用 NYC 和 Chicago 两个城市的交通时序数据、事故标签以及道路、POI、历史碰撞记录三类空间邻接关系，训练交通风险预测模型，并通过前端可视化系统展示不同区域和时间片下的风险分布、真实标签校验、模型指标和空间拓扑解释。

一句话概括就是：后端做交通碰撞风险预测，前端做预测结果的可视化解释。

### 2. 你的研究对象是什么？

答：研究对象是城市区域级交通碰撞风险。项目将城市划分为多个区域网格，将每个区域在每个时间片上的交通状态和事故标签作为样本，预测该区域在目标时间片上的碰撞风险概率。

### 3. 你的项目解决了什么问题？

答：主要解决三个问题：第一，交通碰撞样本少，正负样本不平衡；第二，交通风险具有时间变化和空间关联，普通模型难以同时建模；第三，预测结果如果只用表格展示不够直观，因此需要可视化系统辅助解释。

### 4. 你的系统是实时系统吗？

答：不是。当前系统是离线预测与可视化原型。模型使用本地数据集训练和推理，前端展示的是后端导出的代表性 JSON 样本，没有接入实时交通接口、真实 GIS 地图服务或在线事故上报系统。

### 5. 你的主要工作和改进点是什么？

答：主要包括五点：第一，完成 Attention-LSTM 风险预测框架的复现和双城数据适配；第二，引入自适应平滑门，提升动态特征稳定性；第三，设计 Streaming 后处理，减少输出端预警抖动；第四，完成多模型对比和消融实验；第五，实现前端可视化系统，展示风险热力图、TP/FP/FN 校验、模型指标和空间拓扑解释。

### 6. 你的创新点是什么？是不是完全原创模型？

答：不是从零提出一个全新模型，而是在已有 Attention-LSTM 交通风险预测框架基础上进行改进与实现。本文的改进点主要是动态特征稳定性优化、自适应平滑门、Streaming 后处理、双城实验验证和可视化展示系统。

### 7. 你为什么选择交通碰撞风险预测这个题目？

答：交通碰撞风险具有明显的现实意义。相比普通交通流预测，碰撞风险预测更关注少数高风险事件，对城市交通安全预警有应用价值。同时该任务具有时序依赖、空间关联和类别不平衡等特点，适合用深度时空模型进行研究。

## 二、数据集类

### 8. 你用了哪些数据集？

答：使用 NYC 和 Chicago 两个城市数据集。NYC 包含 13,128 个时间片、64 个区域、116 维特征，共 840,192 个区域-时间样本；Chicago 包含 8,784 个时间片、27 个区域、116 维特征，共 237,168 个样本。

### 9. 一个样本是什么？

答：一个样本可以理解为“某个区域在某个时间片的交通状态及其事故标签”。例如 NYC 有 64 个区域和 13,128 个时间片，因此可以形成 64 × 13,128 个区域-时间样本。

### 10. 数据中的标签是什么？

答：标签是二分类事故标签，0 表示该区域该时间片没有事故或低风险，1 表示存在事故或高风险。模型最终输出的是 0 到 1 之间的风险概率。

### 11. 正样本比例是多少？

答：NYC 正样本比例约 22.53%，Chicago 正样本比例约 13.38%。这说明交通碰撞风险预测是典型的类别不平衡任务。

### 12. 为什么说 Accuracy 容易误导？

答：因为负样本远多于正样本。如果模型把大部分样本都预测为“无事故”，Accuracy 仍然可能较高，但它无法发现真正的风险区域。因此本项目更关注 AUC-PR、F1 和 Recall，尤其是 Recall。

### 13. 116 维特征是什么？

答：数据文件中每个区域每个时间片有 116 维交通相关特征。根据项目参数 `dr=58`，模型内部将其作为 `2 × dr` 的表示维度使用，可以理解为包含区域基础属性和动态交通状态等信息。

### 14. 三类邻接矩阵分别是什么？

答：项目使用三类空间邻接关系：`road_ad.txt` 表示道路连通关系，`poi_ad.txt` 表示 POI 功能相似关系，`record_ad.txt` 表示历史碰撞记录关联关系。这三类图从不同角度描述区域之间的空间影响。

### 15. `threshold_nc.npy` 是什么？

答：它是模型动态演化层使用的门控信号，形状为 `(时间片, 区域数, 1)`。在当前数据中，它与标签值一致，用于控制动态特征在不同状态下的更新程度。

### 16. 为什么前端只展示 13 帧？

答：原始 `.npy` 数据较大，浏览器直接加载全量时序数据会影响性能。因此前端只读取导出的代表性 JSON 样本。完整训练和评估仍在后端基于完整数据完成。

## 三、模型方法类

### 17. 为什么使用 Attention-LSTM？

答：交通碰撞风险既有时间依赖，也有空间关联。LSTM 或 ConvLSTM 可以建模交通状态随时间变化的规律，Attention 可以自适应学习关键邻居区域或关键特征的重要性，因此二者结合适合交通碰撞风险预测任务。

### 18. 你的模型总体流程是什么？

答：模型首先将交通时序数据整理为过去 5 个时间步的输入窗口，然后通过动态演化模块更新风险状态，再通过道路、POI、历史碰撞记录三类邻接图进行空间注意力融合，随后利用 ConvLSTM 进行时空建模，最后通过 Dense + Sigmoid 输出每个区域的风险概率。

### 19. 什么是动态特征演化？

答：动态特征演化是指模型在时间维度上维护区域的动态风险状态。异常发生时，模型更强调当前风险特征；正常时，模型保留并逐步衰减历史动态信息，从而避免稀有异常特征被大量正常样本完全覆盖。

### 20. Update 和 Decay 分别是什么意思？

答：Update 表示当区域出现异常或风险信号时，将当前特征和历史动态状态融合，强化风险状态；Decay 表示当区域处于正常状态时，对历史动态特征进行衰减，避免正常样本反复覆盖历史风险信息。

### 21. 自适应平滑门解决什么问题？

答：它主要解决交通时序数据中短时噪声和局部波动导致动态特征突变的问题。平滑门会根据候选特征与旧特征之间的变化幅度，自动调整保留旧状态和接收新状态的比例，使动态表示更加稳定。

### 22. 平滑门可以怎么通俗解释？

答：如果当前变化像随机噪声，就多保留历史状态；如果当前变化比较稳定或确实代表状态改变，就允许更多新特征进入。它相当于在新旧特征之间加了一个缓冲器。

### 23. 多源空间注意力为什么有必要？

答：交通风险不仅与地理相邻有关，还可能与区域功能相似性和历史事故模式有关。道路邻接、POI 相似和历史碰撞记录分别从不同角度描述区域关联，多源空间注意力可以让模型自动学习不同邻接区域的重要性。

### 24. 为什么不是只用道路邻接图？

答：道路邻接只能描述物理连接关系，无法覆盖功能相似区域和历史风险模式相近区域。例如两个商业区未必直接相邻，但可能有相似的风险模式。因此引入 POI 和历史碰撞关系可以补充道路邻接的不足。

### 25. 你的模型用的是 LSTM 还是 ConvLSTM？

答：项目主模型中使用的是 `ConvLSTM2D`，它用于融合动态特征和静态特征后的时空表示。论文中如果写成 FC-LSTM 或普通 LSTM，需要统一改为 ConvLSTM 或说明 LSTM 类时序建模。

### 26. 为什么输出层用 Sigmoid？

答：因为这是二分类风险预测任务，模型需要输出每个区域属于高风险类别的概率。Sigmoid 可以将输出映射到 0 到 1 之间，便于后续阈值判断和风险展示。

### 27. Streaming 后处理是什么？

答：Streaming 后处理是输出端的稳定化策略。它通过触发阈值和解除阈值形成双阈值滞回机制，避免风险概率在单一阈值附近轻微波动时导致预警状态频繁切换。

### 28. Streaming 后处理和自适应平滑门有什么区别？

答：自适应平滑门作用在模型内部动态特征演化阶段，稳定的是中间特征表示；Streaming 后处理作用在模型输出端，稳定的是最终预警状态。两者位置不同，目标都是减少不必要的抖动。

### 29. Focal Loss 的作用是什么？

答：Focal Loss 用于缓解类别不平衡问题。它会降低容易分类样本对损失的影响，让模型更加关注难分类样本和少数风险样本，从而提升高风险样本识别能力。

### 30. 动态损失项的作用是什么？

答：动态损失项用于约束动态特征不要过度平滑，避免异常状态和正常状态在特征空间中过于接近，从而增强模型对风险变化的区分能力。

## 四、实验与指标类

### 31. 你用了哪些评价指标？

答：使用 AUC-PR、AUC-ROC、F1、Accuracy 和 Recall。由于交通碰撞数据类别不平衡，重点关注 AUC-PR、F1 和 Recall。

### 32. AUC-PR 为什么重要？

答：AUC-PR 更适合类别不平衡任务，因为它关注 Precision 和 Recall 的关系。在正样本较少的交通碰撞预测任务中，它比单纯 Accuracy 更能反映模型识别高风险样本的能力。

### 33. Recall 为什么重要？

答：Recall 表示真实风险样本中被模型识别出来的比例。交通安全预警中漏报代价较高，因此在可接受误报的前提下，应该尽量提高 Recall。

### 34. 你的最终结果是多少？

答：Myplan 在 NYC 上 AUC-PR 为 0.6955，AUC-ROC 为 0.8786，F1 为 0.6443，Accuracy 为 0.7865，Recall 为 0.8265；在 Chicago 上 AUC-PR 为 0.5617，AUC-ROC 为 0.8290，F1 为 0.4730，Accuracy 为 0.7733，Recall 为 0.7055。

### 35. 为什么 Accuracy 不是最高还说模型有效？

答：因为 Accuracy 在类别不平衡任务中可能偏向多数类。交通预警更关注能否识别真实风险区域，因此 Recall、F1 和 AUC-PR 更重要。部分模型 Accuracy 高，但可能对高风险样本识别不足。

### 36. 对比模型有哪些？

答：包括 GSNet、STG2Seq、ConvLSTM、LSTM、LightGBM、CatBoost、XGBoost、LR、ARIMA、HA、SNIPER 和 Myplan。答辩时不需要逐个解释，只要说明覆盖传统统计、传统机器学习、时序模型和交通预测相关模型。

### 37. ARIMA 为什么效果差？

答：ARIMA 更适合相对平稳的线性时间序列，而交通碰撞风险具有明显非线性、突发性和空间关联，因此传统统计模型难以充分建模。

### 38. XGBoost、CatBoost 为什么不如你的模型？

答：它们在结构化数据上表现较好，但难以直接处理复杂的时间依赖和多源空间拓扑关系。交通碰撞风险既有时序变化又有空间传播，深度时空模型更适合这类任务。

### 39. 消融实验验证了什么？

答：消融实验验证自适应平滑门和 Streaming 后处理的作用。完整模型相比去除相关模块后的配置，在 AUC-PR、F1 和 Recall 等指标上整体更稳定，说明这些模块对风险识别和输出稳定有帮助。

### 40. 指标从哪里来的？

答：指标首先整理在 `docs/paper/p1结果展示.md` 的模型对比表和消融实验表中，然后通过 `export_frontend_metrics.py` 导出为 `results/frontend_metrics.json` 供前端展示。论文整理版表格见 `docs/paper/论文表格汇总.md`。

### 41. 为什么 `results/metrics.jsonl` 是空的？

答：`results/metrics.jsonl` 是重新运行 `train.py` 时追加写入的训练日志文件。当前答辩展示使用的是已经整理好的实验结果表和前端指标 JSON，因此不依赖这个空日志文件。

## 五、系统实现类

### 42. 前端系统做了什么？

答：前端系统展示模型预测结果，包括城市切换、时间轴播放、风险热力图、区域详情、TP/FP/FN 标签校验、模型指标对比、消融实验展示和空间拓扑解释。

### 43. 前端使用什么技术？

答：前端是单文件 HTML 页面，主要使用 React、TailwindCSS 和 ECharts，通过本地 HTTP 服务读取 `results/` 目录下的 JSON 文件并进行可视化展示。

### 44. 前端读取哪些数据？

答：主要读取 `results/frontend_predictions_nyc.json`、`results/frontend_predictions_chicago.json`、`results/frontend_metrics.json`、`results/frontend_topology.json` 和 `results/frontend_runtime_meta.json`。

### 45. 为什么不能直接双击 HTML？

答：因为浏览器直接打开本地 HTML 时，可能因为本地文件访问限制无法正常加载 JSON。应在项目根目录启动 HTTP 服务，例如 `python -m http.server 8000`，再访问 `dashboard_fixed.html`。

### 46. TP、FP、FN 分别是什么意思？

答：TP 表示模型成功命中真实风险，FP 表示模型误报风险，FN 表示真实有风险但模型漏报。交通安全预警中 FN 的代价较高，因此需要重点关注 Recall。

### 47. 前端展示的是真实数据吗？

答：核心预测概率、流量特征、真实标签校验、模型指标和拓扑关系来自本地数据和模型导出结果。但前端只展示抽取的代表性时间帧，部分区域名称或展示文案用于增强可读性。

### 48. 可视化系统有什么价值？

答：它让模型结果更直观。除了展示风险概率，还能展示风险空间分布、时间变化、真实标签校验和邻接关系解释，有助于答辩展示和结果分析。

### 49. 为什么要导出 JSON？

答：原始 `.npy` 数据很大，不适合浏览器直接加载。导出 JSON 可以保留代表性样本和关键指标，同时保证前端交互流畅。

### 50. 系统有哪些不足？

答：当前系统是离线原型，没有接入实时交通接口和真实 GIS 地图边界；前端展示的是代表性样本而非全量数据；后续可以接入实时交通流、天气、施工、大型活动等外部因素。

## 七、老师可能追问的尖锐问题

### 56. 这个模型是不是你原创的？

答：基础 Attention-LSTM 框架并不是完全从零原创。本文主要是在已有框架基础上完成复现、双城数据适配、平滑门与后处理改进、实验验证和可视化系统实现。

### 57. 如果老师问“平滑门是不是只是简单加权平均”怎么办？

答：可以回答：形式上确实是新旧特征的加权融合，但关键在于权重不是固定的，而是由候选特征和历史特征之间的变化幅度通过可学习门控函数得到。因此它能够根据不同状态自适应调节更新比例。

### 58. 如果老师问“Streaming 后处理是不是人工调参”怎么办？

答：可以回答：Streaming 后处理属于输出端稳定化策略，核心目的是减少阈值附近的预警抖动。它不改变模型学习到的风险概率，而是在应用层面将概率转化为更稳定的预警状态。

### 59. 如果老师问“为什么不是实时系统”怎么办？

答：可以回答：本文重点是风险预测模型和可视化原型验证，当前阶段使用离线数据完成训练、评估和展示。实时系统需要额外接入交通接口、在线推理服务和 GIS 地图服务，属于后续扩展方向。

### 60. 如果老师问“前端是不是只是展示，没有研究价值”怎么办？

答：可以回答：前端不是算法创新点，但它承担了模型结果解释和系统验证作用。通过风险热力图、TP/FP/FN 校验、模型指标和空间拓扑解释，可以更直观地分析模型预测结果，增强系统完整性。

### 61. 如果老师问“为什么不用更先进的 GNN”怎么办？

答：可以回答：GNN 确实适合图结构建模。本文采用多源空间注意力机制对三类邻接关系进行加权聚合，本质上也是在建模区域间的图结构影响。后续可以进一步尝试 GCN、GAT 或时空图神经网络进行扩展。

### 62. 如果老师问“为什么不直接用 Transformer”怎么办？

答：可以回答：Transformer 对长序列建模能力强，但对数据规模、训练成本和参数设置要求更高。本文任务中历史窗口长度较短，且需要结合空间邻接关系，因此采用 Attention 与 LSTM/ConvLSTM 结合的结构更轻量，也更容易解释。

## 九、模型细节深挖（老师如果看过你代码才会问）

### 71. Evolution 层为什么乘 e^(-1/2)？这个值怎么来的？

答：e^(-1/2) ≈ 0.6065，是一个经验性的衰减因子。作用是在候选特征生成时做一次全局压缩，防止 sigmoid 激活后特征值持续累积过大。不是必须这个值，但它配合后续的平滑门，让特征更新过程在数值上更稳定。论文里可以解释为"时间衰减因子"。

### 72. smooth_gate_logit 初始化为 -0.5 是什么意思？

答：sigmoid(-0.5) ≈ 0.38。这意味着初始状态下平滑门输出约 0.38，即新特征混合时约 62% 来自候选、38% 来自旧特征——默认偏向接受新信息。随着训练推进，logit 会根据数据自适应调整。

### 73. threshold_nc 的形状是 (T, R, 1)，为什么最后一维是 1？

答：每个区域每个时间步只需要一个门控信号值。这个值和 label 一样，有事故为 1、没事故为 0。在代码中用 `tf.repeat(threshold_nc, dr2, axis=-1)` 广播到 dr2（116）维，让门控信号能作用到每个特征维度上。

### 74. 为什么 MultiAttention 里要传播 6 轮（number_sp=6）？

答：每轮传播相当于消息传递（message passing）中的一跳——第一轮学直接邻居，第二轮学邻居的邻居，以此类推。6 轮意味着每个区域最多可以感知 6 跳范围内的邻居信息。选 6 是基于 NYC 的 10×10 网格——6 跳足以覆盖对角线两端的区域，保证信息可以传播到整个图。

### 75. MultiAttention 里 w_poi、w_road、w_record 三个权重是向量不是标量？

答：是的，三个权重都是形状为 (116,) 的可训练向量，不是单个标量。这意味着每个特征维度对三类空间关系的偏好可以不同——有些维度可能更依赖道路连接，有些维度更依赖 POI 相似性。这是比简单标量加权更精细的设计。

### 76. 为什么把 MultiAttention 分成两个独立的实例——一个处理动态特征、一个处理静态特征？

答：静态特征（如 POI 分布、道路密度）和动态特征（如实时流量、速度）的空间依赖规律完全不同。POI 功能相似是固定的，但交通拥堵的传播方向是随时间变化的。分开建模让两个 MultiAttention 各自学习最适合自己特征类型的空间模式，不会互相干扰。

### 77. dy_loss = max(0, a_dy - MAE(dy_diff, 0)) 这公式怎么理解？

答：dy_diff 是相邻时间步之间的特征变化。MAE(dy_diff, 0) 越大说明特征变化越大。如果 MAE 大到超过 a_dy（=6），括号内变负，max 取 0——模型满意，不做惩罚。如果 MAE 太小（特征几乎不变），括号内为正，产生惩罚。本质上是在鼓励模型保持一定的时序敏感度，防止特征退化到静止状态。

### 78. Evolution 层返回的 all_data_dynamic_diff 有什么用？训练之外用吗？

答：all_data_dynamic_diff 记录了每个时间步的特征差分序列，专门用于计算 dy_loss。它只在训练阶段有价值（让模型学会保持时序敏感性），推理阶段虽然也返回但不需要使用。可以看作是为了 dy_loss 专门保留的训练辅助输出。

### 79. prepare_data 函数为什么要舍弃前 len_recent_time 个时间步？

答：因为滑动窗口需要 len_recent_time（=5）个历史时间步才能构成一个完整样本。第 0 到第 4 个时间步之前没有足够的历史数据填满窗口。所以最终可用样本数是 总时间步 - len_recent_time。NYC：13128 - 5 = 13123，Chicago：8784 - 5 = 8779。

### 80. max_neigh 为什么设成 4？不是每个区域平均有 11 个邻居吗？

答：设成 4 是一种工程权衡。虽然平均有 11 个邻居，但取太多邻居会导致注意力计算量增大（O(N × K²)）、过拟合风险增加。4 个最相关的邻居已经能捕捉主要的空间依赖，剩下的邻居贡献较小。这是一个可以调的超参。

### 81. get_neigh_index 截断邻居时如果不足 max_neigh 个怎么办？

答：用区域自身的 ID 填充到 max_neigh 个。这意味着当一个区域邻居不够时，多余的"假邻居"指向自己——自循环在注意力计算中相当于"我自己的特征也作为邻居信息的一部分"，不会引入外部噪声。

## 十、训练过程与超参追问

### 82. batch_size=25 是怎么选的？

答：这是 GPU 显存和训练效率之间的平衡。NYC 每个样本是 (5, 64, 116) 的 float32 张量，batch_size=25 时每个 batch 约 3.7MB，加上中间激活可以装进消费级显卡。更大的 batch_size 可能导致 OOM，更小则训练变慢。没有做过系统的 batch_size 调优。

### 83. 训练 100 个 epoch，加了早停（patience=10），实际训练了多少轮？

答：取决于验证集上的 loss 下降速度。早停在连续 10 个 epoch 无改善时触发。通常实际训练轮数在 30-60 轮之间，具体数值取决于数据集和随机种子。NYC 数据量大、模式多，可能需要更多轮；Chicago 数据量小、更容易早停。

### 84. 为什么不直接用验证集上的最佳 F1 来选模型，而是用 loss？

答：早停监控的是 loss 而不是 F1，因为 loss 更平滑、稳定。F1 依赖于阈值选择，在小批量上波动较大，容易误触发早停。最终评估时再在测试集上用网格搜索确定最佳阈值和对应的 F1。

### 85. learning_rate=0.001 有没有调过？用的是什么优化器？

答：代码中配置了 learning_rate=0.001，没有显式看到学习率衰减或 warmup 策略。优化器应该是 TensorFlow 默认的 Adam（代码中未显式指定）。这是深度学习中相对标准的初始配置，对于本项目规模的数据和模型来说通常够用。

### 86. 数据有没有做标准化？特征值范围是多少？

答：特征值范围在 [-3, 3] 之间，均值为 0.62-0.71，标准差约 0.95-0.96。说明数据已经做过某种形式的标准化（可能是 Z-score 或 min-max），不需要额外处理。无缺失值（NaN）和无穷值（Inf），数据质量较好。

### 87. 有没有做数据增强？

答：没有。交通时序数据不适合常规的图像增强（旋转、裁剪）。可以考虑的增强方式包括：加微小高斯噪声模拟传感器误差、随机屏蔽部分时间步做鲁棒性训练，但这些没有在项目中实施。

## 十二、统计与数学基础追问

### 93. 二分类任务用 Sigmoid 输出，怎么选阈值？

答：训练阶段在验证集上以 0.001 步长从 0 到 1 网格搜索，找到使 F1 最大的阈值（threshold_f1）和使 Accuracy 最大的阈值（threshold_accu）。推理阶段取两个阈值下较优的 F1 作为最终结果。后处理阶段叠加双阈值滞回，实际触发预警和解除预警使用不同的阈值。

### 94. Focal Loss 的 γ=2、α=0.25 是怎么选的？

答：这是何恺明 2017 年原始论文推荐的标准配置，在多个不平衡任务上验证有效。本项目没有单独调过这两个参数，直接沿用了论文里报告的最优值。如果要做系统调优，可以在 α∈{0.25, 0.5, 0.75}、γ∈{0, 1, 2, 3, 5} 的组合上做网格搜索。

### 95. AUC-PR 怎么算的？和 AUC-ROC 计算上有什么不同？

答：两个都是遍历所有可能的阈值计算曲线下面积。区别在于：ROC 曲线的坐标是 (FPR, TPR)——FPR=FP/(FP+TN)；PR 曲线的坐标是 (Recall, Precision)——完全不涉及 TN。因为 TN 数量巨大（65万负样本），ROC 在类别不平衡时会"美化"模型表现。

### 96. 为什么 SNIPER 的 Chicago Recall 只有 0.27 但 Accuracy 有 0.89？

答：Chicago 正样本只有 13%。SNIPER 如果"几乎不报警"（阈值设得很高），把大部分样本判为安全：87000 个负样本中有 85000+ 个判对 → TN 巨大 → Accuracy = (TP+TN)/总数 自然高。但也意味着 73% 的真实事故没被识别出来。这是 Accuracy 陷阱的教科书级案例。

### 97. 你的模型参数量约 37 万，算是大模型还是小模型？

答：在深度学习里算轻量级的。作为对比：ResNet-50 约 2500 万参数，BERT-base 约 1.1 亿参数，GPT-3 约 1750 亿参数。37 万参数意味着训练快、推理快、功耗低，适合小规模数据集和原型验证。

### 98. 有没有试过更大的模型？更深、更宽？

答：没有。当前模型已经能满足实验需求，加深加宽可能带来过拟合（尤其 Chicago 数据量小）和训练成本增加。但从学术完整度来说，报告一下模型参数量和复杂度分析是应该做的。

## 十三、文献与相关工作追问

### 99. Attention-LSTM 的原始出处是什么？你参考了哪篇论文？

答：Attention 和 LSTM 各自有大量文献。LSTM 原始论文是 Hochreiter & Schmidhuber, 1997。Attention 机制在 2014-2017 年间由 Bahdanau（机器翻译）和 Vaswani et al.（Transformer）等人推动成熟。将 Attention 和 LSTM 结合用于时空预测的方法在交通领域有多篇论文。本文参考了这些已有工作，在此基础上加入平滑门和后处理改进。

### 100. ConvLSTM 原论文是哪篇？

答：Shiet al., 2015, "Convolutional LSTM Network: A Machine Learning Approach for Precipitation Nowcasting", NeurIPS。香港科技大学提出，用于降水临近预报。核心思路是把 LSTM 门控公式中的全连接换成卷积，保留输入的空间结构。

### 101. Focal Loss 原论文是哪篇？

答：Lin et al., 2017, "Focal Loss for Dense Object Detection", ICCV。何恺明团队提出，最初用于目标检测中解决正负样本不平衡问题。本文将其迁移到交通碰撞风险预测的类别不平衡场景。

### 102. 你参考的 GSNet、STG2Seq、SNIPER 分别来自哪里？

答：这三个都是近年来交通预测领域的已发表模型。本文将它们作为对比基线复现。具体论文出处需要查文献库，答辩时如果被问到可以说"来自交通预测相关论文，本文基于论文描述进行了复现和统一评估"。关键是讲清楚你复现了、统一跑了实验。
