PART 01 · 问题定义

城市交通碰撞风险的三个核心挑战

CHALLENGE 01

时间波动性

早晚高峰、节假日时段事故风险显著变化。当前风险受过去多个时间片的交通状态累积影响，传统统计方法难以捕捉长程时序依赖。

CHALLENGE 02

空间关联性

相邻区域存在风险传播和相似变化。单一区域建模丢失空间上下文——一个路口堵了，周边大概率也出问题。

CHALLENGE 03

类别不平衡

高风险样本远少于正常样本。模型若偏向多数类，Accuracy 好看但漏掉真正高风险点——这在预警场景中不可接受。

核心问题：传统方法难以同时处理时间依赖和空间关联。类别不平衡下，发现高风险样本比追求准确率更重要。

PART 03 · 方法

Attention-LSTM 模型结构

输入层 · INPUT
116维时序特征 × 历史窗口 + 道路/POI/记录 三种邻接矩阵，共同描述每个时间片的交通状态和空间上下文。
编码层 · ENCODER（核心）
LSTM：学习历史交通状态的时序依赖关系。
Attention 机制：突出关键时间片和关键特征——不是所有历史时刻同等重要。
输出层 · OUTPUT
编码表示 → 风险概率 → 阈值判断 + 平滑门 / 后处理 → 高风险 / 低风险分类结果。
核心思路：LSTM 学习交通随时间变化的规律，Attention 突出关键信息，两者结合更好地识别高风险样本。

PART 03 · 方法

平滑门 & Streaming 后处理

问题 · PROBLEM

预测输出频繁跳变

交通风险在连续时间片具有连续性。如果预测在阈值附近反复横跳——"高风险"→"安全"→"高风险"——预警系统失去可操作性。

方案 · SOLUTION

自适应平滑门：作用于模型内部动态特征，使风险表示更稳定。
Streaming 后处理：作用于输出端，类似迟滞比较器，减少概率在阈值附近频繁波动。

平滑门和后处理不是替代模型主体，而是对风险变化和输出结果做稳定化——消融实验将验证其有效性。

结果解读

NYC 数据量大、正样本 22.53%，Recall 82.65%——模型能识别超八成高风险样本。

Chicago 正样本仅 13.38%，难度更大，但仍取得 70.55% 的 Recall，模型未崩溃。

AUC-ROC 在两个城市均超过 0.82，说明模型整体排序能力良好。

关键结论：模型在两个城市数据集上均具备较好的高风险样本识别能力——这对交通安全预警任务比 Accuracy 更重要。

PART 04 · 消融

模块有效性验证

配置NYC RecallChicago Recall
去平滑门 + 去流式后处理0.71080.6318
去平滑门0.80460.6693
去流式后处理0.74070.6401

完整模型在所有配置中 Recall 最高。全部去除时 NYC Recall 从 0.8265 降至 0.7108——差距超过 11 个百分点。
平滑门的作用

去掉平滑门后 NYC Recall 0.8265 → 0.8046，Chicago 0.7055 → 0.6693。平滑门提升动态特征表达稳定性。

后处理的作用

去掉后处理后 NYC Recall → 0.7407，Chicago → 0.6401。Streaming 后处理有效减少输出端频繁抖动。

结论

平滑门管内部稳定性，后处理管外部输出——两者在不同环节互补，配合效果最优。

PART 06 · 展望

不足与未来方向

当前不足
离线原型系统

尚未接入实时交通数据接口和真实 GIS 地图边界，前端展示为代表性样本。

外部因素有限

未融合天气、施工信息、大型活动等对交通风险有显著影响的外部环境数据。

前端受限于浏览器性能

展示的是导出样本而非全量数据实时渲染。

未来方向
引入多源外部数据

融合天气、施工信息、大型活动日历等，丰富特征空间，提升预测精度。

在线预测与实时预警

从离线扩展到流式数据接入和在线推理，实现真正的实时碰撞风险预警。

接入真实 GIS + 可解释增强

替换抽象区域网格为真实道路网络和地理边界。增加模型决策归因分析，辅助交通管理决策。
