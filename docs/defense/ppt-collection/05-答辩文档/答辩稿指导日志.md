# 指导教师答辩稿指导日志

## 第一次指导

时间：2026 年 5 月上旬  
地点：线上 / 线下指导  
指导主题：答辩稿整体结构与汇报主线梳理

指导内容：

1. 指导教师对答辩稿初稿进行了整体审阅，认为稿件已经能够覆盖研究背景、数据构建、模型设计、实验结果和系统展示等主要内容，但不同部分之间的衔接还需要进一步压缩和梳理。
2. 教师指出，答辩稿开头应先说明课题名称和研究目标，再引出“交通碰撞风险预测”这一应用场景，避免一开始直接进入模型细节，导致评委难以快速把握选题意义。
3. 教师建议将项目定位表述为“离线交通碰撞风险预测与可视化分析原型系统”，明确其基于 NYC 和 Chicago 双城数据完成训练、评估和展示，不应表述为已经接入真实道路实时接口的生产系统。
4. 教师要求答辩稿突出本课题的完整流程，即从数据预处理、Attention-LSTM 模型训练、实验对比、消融验证到前端可视化展示，体现毕业设计的工程闭环。

修改意见：

- 调整答辩稿开场部分，先讲清楚研究对象、应用场景和系统目标。
- 将研究背景与问题分析压缩为 1 分钟左右，重点说明交通碰撞风险具有时序依赖、空间关联和类别不平衡等特点。
- 在技术路线部分增加“数据构建、模型训练、实验验证、前端展示”的连续逻辑。
- 避免将系统夸大为实时交通平台，统一使用“离线预测”“可视化原型”“前端展示系统”等表述。

## 第二次指导

时间：2026 年 5 月中旬  
地点：线上 / 线下指导  
指导主题：模型方法与实验结果表达优化

指导内容：

1. 指导教师重点检查了模型方法部分的讲稿，认为 Attention-LSTM 的作用需要用更适合口头答辩的语言说明，不能只罗列模型模块名称。
2. 教师建议在讲述 LSTM 时强调其用于捕捉交通状态随时间变化的依赖关系；在讲述 Attention 机制时强调其用于突出关键时间片和关键特征，使模型更关注对风险预测贡献较大的信息。
3. 教师指出，实验指标部分不能只讲 Accuracy，应结合交通碰撞样本类别不平衡的特点，重点解释 Recall、F1 和 AUC-PR 的意义。尤其要说明 Recall 较高意味着模型能够发现更多潜在高风险样本，减少漏报。
4. 教师要求在汇报实验结果时给出核心数值，例如 NYC 数据集上的 AUC-PR、AUC-ROC、F1、Recall，以及 Chicago 数据集上的对应指标，使答辩陈述更有依据。

修改意见：

- 将模型介绍改为“为什么这样设计”的表达方式，而不是单纯介绍模块结构。
- 在答辩稿中补充 Attention-LSTM、平滑门和流式后处理的作用说明。
- 实验结果部分重点呈现 AUC-PR、AUC-ROC、F1 和 Recall，弱化单一准确率叙述。
- 增加消融实验说明，强调完整模型在双城数据集上 Recall 均优于去除关键模块后的版本。

## 第三次指导

时间：2026 年 5 月中旬  
地点：线上 / 线下指导  
指导主题：PPT 页面对应关系与时间控制

指导内容：

1. 指导教师对答辩 PPT 大纲和逐页讲稿进行了核对，建议答辩稿必须与 PPT 页码保持一致，避免现场出现讲稿内容与页面展示不匹配的问题。
2. 教师建议将 PPT 控制在 12 到 14 页左右，按照“封面、背景、数据、技术路线、模型结构、实验设计、实验结果、消融实验、系统展示、部署运行、总结展望”的顺序组织。
3. 教师指出，答辩时间如果为 8 分钟，应减少背景和数据集介绍的篇幅，把主要时间留给模型方法、实验结果和系统展示；如果时间被压缩，应优先保留研究目标、核心方法、关键结果和系统定位。
4. 教师要求准备 8 分钟版、5 分钟版和 1 分钟打断版讲稿，以应对不同答辩现场节奏。

修改意见：

- 按 PPT 顺序重新整理答辩稿，使每一页都有对应讲述内容。
- 压缩重复性背景表述，避免在研究背景、数据说明和总结中反复出现同一段内容。
- 保留关键实验指标和系统演示说明，确保即使压缩时间也能讲清楚项目成果。
- 准备简短过渡语，例如“接下来介绍数据构建”“下面看实验结果”“最后说明系统实现与不足”。

## 第四次指导

时间：2026 年 5 月下旬  
地点：线上 / 线下指导  
指导主题：系统演示、问答准备与最终定稿

指导内容：

1. 指导教师检查了前端可视化展示部分的讲稿，认为应重点说明系统展示的数据来源和展示边界。前端读取的是后端导出的 JSON 样本，而不是直接加载完整 `.npy` 文件。
2. 教师建议系统展示时突出风险热力图、时间轴播放、TP / FP / FN 标签校验、模型指标对比和局部空间邻接解释等功能，体现模型结果具有可视化和可解释展示能力。
3. 教师提醒，答辩问答中可能会被问到数据集来源、类别不平衡处理、为什么选择 Attention-LSTM、为什么关注 Recall、系统是否实时运行、后续如何改进等问题，需要提前准备简洁回答。
4. 教师对最终答辩稿进行了复查，认为整体内容已经能够支撑正式答辩，但需要在语速、停顿和时间分配上继续练习，保证现场表达自然清楚。

修改意见：

- 在系统展示部分明确说明：当前系统是离线预测与可视化分析原型，不是实时生产级交通平台。
- 准备常见问题回答，重点围绕模型选择、评价指标、实验结果、系统边界和未来工作展开。
- 答辩结尾应总结项目完成了数据构建、模型训练、实验评估和前端展示的完整流程。
- 正式答辩前再次检查 PPT、讲稿、演示页面、项目运行说明和备份材料，确保材料一致。

## 总结

通过多次指导，答辩稿由最初的内容堆叠式说明，逐步调整为以研究问题为起点、以 Attention-LSTM 风险预测模型为核心、以实验结果和前端可视化系统为支撑的完整汇报稿。最终稿能够较清楚地说明课题背景、技术路线、模型设计、实验结论、系统实现和不足展望，可作为毕业设计正式答辩的讲稿依据。
