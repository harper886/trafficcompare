# 答辩问答准备

## 1. 前端展示的数据是真实的吗？

答：不是全部都是原始真实数据，但核心展示数据来自真实数据和模型结果导出。

本系统后端使用 NYC 和 Chicago 的交通时序数据、事故标签和空间邻接关系进行训练与评估。前端默认加载 `results/frontend_predictions_nyc.json`、`results/frontend_predictions_chicago.json`、`results/frontend_metrics.json` 和 `results/frontend_topology.json`，其中包含模型预测概率、流量特征、真实标签校验结果和拓扑邻接信息。

为了提升可读性，页面中的部分区域名称、天气描述、功能区描述属于可视化语义映射；如果外部 JSON 加载失败，系统会使用内置演示数据作为兜底。

## 2. 为什么前端只展示 13 个时间帧？

答：因为原始 `.npy` 时序数据较大，直接在浏览器中加载全量数据会影响交互性能。

项目采用后端导出方式，从完整时序数据中抽取具有代表性的时间帧，生成前端可读的 JSON。这样既能展示模型在不同时间片上的风险变化，又能保证页面流畅运行。完整训练和实验评估仍基于后端数据完成。

## 3. 为什么要使用 Attention-LSTM？

答：交通碰撞风险具有明显的时序依赖和局部波动特征，LSTM 适合建模时间序列变化；Attention 机制可以突出关键时间片和关键区域特征，提升模型对高风险状态的关注能力。

相比普通 LSTM，Attention-LSTM 更容易解释模型为什么在某些时间片或区域给出较高风险预测。

## 4. 为什么重点关注 Recall？

答：交通碰撞预警场景中，漏报的代价通常高于误报。

如果模型漏掉真实高风险区域，可能导致安全风险无法提前发现。因此本系统更强调召回率，在可接受误报范围内尽量减少漏报。这也是预警系统中常见的“召回优先”设计思想。

## 5. Accuracy 不是最高，为什么模型仍然有效？

答：交通碰撞数据存在类别不平衡，负样本远多于正样本。只追求 Accuracy 可能导致模型倾向于预测“无事故”，看似准确率高，但实际无法发现风险。

因此本文同时使用 AUC-PR、AUC-ROC、F1 和 Recall 进行综合评估。其中 AUC-PR 和 Recall 更能反映模型识别少数高风险样本的能力。

## 6. 消融实验说明了什么？

答：消融实验用于验证模型中关键模块的有效性。

从结果看，完整模型在 NYC 和 Chicago 上都取得更高的 AUC-PR、AUC-ROC、F1 和 Recall，说明平滑门和流式后处理对稳定模型输出、提高风险识别能力有帮助。

## 7. 系统是不是实时交通系统？

答：不是。本系统定位为交通碰撞风险预测与可视化原型系统。

当前版本使用本地数据集、离线训练结果和导出的前端 JSON 进行展示，没有接入实时交通接口或实时事故上报系统。后续可以扩展实时数据接入、地图坐标对齐和在线更新模块。

## 8. 为什么 GitHub 下载后数据集可能损坏？

答：项目中的 `.npy` 和 `.h5` 文件较大，使用 Git LFS 管理。如果直接使用 GitHub 的 Download ZIP，可能只下载到 LFS 指针文件，而不是完整数据。

正确方式是：

```powershell
git lfs install
git clone https://github.com/harper886/trafficcompare.git
cd trafficcompare
git lfs pull
```

如果已经 clone 过项目，则在项目目录执行：

```powershell
git lfs pull
```

## 9. 前端如果显示演示数据怎么办？

答：通常是因为浏览器没有成功读取 `results/` 目录下的 JSON 文件。

解决方式是不要直接双击 HTML 文件，而是在项目根目录运行：

```powershell
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000/dashboard_fixed.html
```

## 10. 项目的创新点可以怎么讲？

答：可以从三个层面讲：

1. 模型层面：结合 Attention-LSTM、平滑门和流式后处理，提高交通碰撞风险预测的稳定性和召回能力。
2. 数据层面：同时考虑交通时序特征、事故标签和空间邻接关系，支持 NYC 和 Chicago 双城实验。
3. 可视化层面：将预测概率、真实标签校验、模型指标和空间拓扑解释融合到前端大屏中，便于答辩展示和结果解释。

## 11. 老师问“你这个系统有什么不足”怎么回答？

答：可以主动说明边界：

当前系统仍是离线原型系统，尚未接入实时交通接口；前端展示采用代表性时间帧抽样，而不是全量数据直接加载；区域语义描述和部分展示文案用于增强可读性，后续可以进一步接入真实 GIS 边界、天气数据、施工事件和实时事故数据。

## 12. 最推荐的答辩总结话术

本项目围绕交通碰撞风险预警问题，构建了包含交通时序数据、事故标签和空间邻接关系的双城实验数据，设计并训练了 Attention-LSTM 风险预测模型，通过多模型对比和消融实验验证模型有效性，并进一步实现了前端可视化大屏，用于展示风险热力图、真实标签校验、模型指标和空间邻接解释。系统目前定位为离线预测与可视化原型，为后续接入实时交通数据和真实地图服务提供了基础。
